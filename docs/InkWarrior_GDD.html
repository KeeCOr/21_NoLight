InkWarrior

  • 문서 유형: 게임
  • 문서 버전: 1.0
  • 프로젝트 버전: 0.12.0
  • 근거 신뢰도: medium

1. 문서 메타데이터와 근거 범례

  • [사실] package.json: name 21-nl, version 0.12.0, description "Ink-brush action platformer", Electron+Phaser 3.60, Jest 테스트 러너 구성.
  • [사실] 리포지토리에 InkWarrior_기획서.md/html, persona_playtest_feedback.md, next_improvement_instruction.md 등 기획 문서 다수 존재(본문 미열람).
  • [제안] 본 GDD는 파일명·구성·에셋 목록에서 추론한 내용을 포함하며, 문서 본문 대조 검증이 필요함을 명시.

2. 문제 정의

  • 붓(잉크)을 무기로 삼는 액션 플랫포머 장르에서, 기존 작품 대비 '먹으로 그리듯 베는' 손맛과 리듬감 있는 콤보 피드백이 부족하다는 문제의식에서 출발(제안).
  • 카메라 임팩트, 콤보 히트 리액션 관련 테스트 파일이 다수 존재해, 타격감(히트스탑·카메라 흔들림) 튜닝이 핵심 개발 과제로 다뤄지고 있음을 시사(사실: 테스트 파일 존재 기준).

3. 한 줄 피치와 제품 포지셔닝

먹과 붓을 다루는 전사가 되어, 한 획의 슬래시로 적을 베어내는 잉크 브러시 액션 플랫포머(제안, 미검증).
PC(Windows) Electron 포터블 실행 파일로 배포되는 인디 규모 싱글플레이어 액션 게임으로 포지셔닝(사실: 빌드 산출물 확인).

4. 주 페르소나

이름: 김도윤, 27세, 스타트업 프론트엔드 개발자, 퇴근 후 20~30분 단위로 짧게 즐길 수 있는 하드코어 액션 게임을 찾음(제안, 미검증).
콤보와 타이밍 기반 전투에 익숙하며, 반복 플레이를 통한 실력 향상 곡선을 선호(제안).
데스크톱(PC) 환경에서 마우스/키보드 또는 게임패드로 플레이(사실: Electron 데스크톱 빌드 기준).

5. 디자인 기둥과 핵심 재미

  • 붓질 같은 슬래시 액션(brush-slash, combo-brush-smear 에셋 존재)과 콤보 연계의 손맛(사실: 관련 에셋 파일명 확인, 재미 요소 해석은 제안).
  • 흡수(absorb)·전기(electric) 계열 특수 능력 캐릭터 존재를 시사하는 에셋명으로, 속성 기반 전투 다양성이 기둥 중 하나로 제안됨.
  • 타격 시 카메라 임팩트·히트 리액션을 통한 강한 피드백(제안, CameraImpact 관련 테스트 존재는 사실).

6. 핵심 루프

유저가 선택을 하면 결과가 되고, 그 결과 때문에 다시 선택을 한다.

적을 관찰한다 → 붓을 휘둘러 슬래시 콤보로 공격한다 → 히트 피드백(카메라 임팩트, 이펙트)을 받는다 → 적을 처치하거나 회피/방어한다 → 다음 구간으로 진행하며 난이도가 상승한다 → 다시 적을 관찰한다(제안, 미검증 순환 문장).

7. 최초 30초 플레이 흐름

  • 게임 실행 후 스테이지 배경(bg_far/bg_mid/bg_fog 등 다중 레이어)이 표시됨(사실: 관련 에셋 파일 확인).
  • 플레이어는 이동 및 기본 슬래시 공격을 시도해보며 조작감을 익힘(제안).
  • 초반 적과 조우해 첫 콤보 히트와 카메라 임팩트를 경험함(제안).

8. 게임 규칙과 승패 조건

  • 스테이지 클리어: 구간 내 적을 처치하거나 목표 지점 도달 시 성공(제안).
  • 스테이지 실패: 플레이어 체력 소진 시 실패하며, 실패 SFX(sfx_stage_fail.ogg) 존재 확인(사실: 오디오 파일 존재).
  • 피격 시 sfx_player_hurt.ogg, 적 처치 시 sfx_enemy_defeat.ogg 재생(사실: 파일 존재, 정확한 트리거 조건은 미검증).

9. 콘텐츠, 진행, 성장, 경제 구조

  • 캐릭터 매니저(CharacterManager) 및 밸런스 설정(BalanceConfig) 테스트 존재로 보아, 다중 캐릭터/속성(흡수, 전기 등)과 수치 밸런싱 시스템이 구현되어 있음을 시사(사실: 테스트 파일 존재).
  • 경제(재화, 상점) 구조에 대한 근거 파일은 확인되지 않아 현재 범위 밖으로 판단(제안).

10. MVP 가설과 검증 방법

  • 가설1: 붓질 기반 슬래시 콤보와 강한 히트 피드백(카메라 임팩트)이 있으면 플레이어가 반복 플레이 의향을 가질 것이다(제안).
  • 가설2: 속성별(흡수/전기) 캐릭터 차별화가 전투 다양성에 대한 만족도를 높일 것이다(제안).
  • 검증 방법: 페르소나 대상 플레이테스트 세션 후 재플레이 의향 및 콤보 성공률 설문/로그 수집(제안, 실제 실행 여부는 미검증).

11. 레퍼런스별 핵심 행동 단계 수와 적용 교훈

  • 참조 문서 docs/superpowers/specs/2026-05-14-action-platformer-design.md: 액션 플랫포머 핵심 행동 단계 구조를 정의한 것으로 추정되나 본문 미열람으로 단계 수는 확인 불가(사실: 문서 존재, 내용은 미확인).
  • 참조 문서 2026-05-18-shark-scale-combat-design.md: 전투 스케일링 관련 설계 문서로 추정, 콤보 난이도 곡선 설계에 참고된 것으로 제안.

[제안] 액션 플랫포머 벤치마크의 핵심 행동은 적 패턴 관찰 → 회피·공격 입력 → 다음 구간 진입의 3단계다. 적용 교훈은 붓질 방향과 유효 판정을 색상뿐 아니라 실루엣·궤적으로도 즉시 구분하게 하는 것이다.

12. 수치 KPI와 측정 방법

  • KPI 제안: 스테이지 평균 클리어 성공률 60% 이상 — 스테이지 종료 이벤트 로그(성공/실패 카운트) 측정(제안, 실제 로깅 구현 여부 미검증).
  • KPI 제안: 평균 콤보 연계 히트 수 5회 이상 — 전투 중 콤보 카운터 로그 집계(제안).
  • 위 수치는 검증 목표로 제시된 것이며 실측 데이터는 없음(사실: 계측 코드 존재 여부 미확인).

13. UI, HUD, 컨트롤

  • 상태1(대기): 스테이지 시작 전 배경만 표시.
  • 상태2(전투 중): HUD 브러시 게이지(hud_brush_bar.png)와 아이템 슬롯(hud_item_slot.png) 표시(사실: 에셋 파일 확인).
  • 상태3(히트 리액션): 콤보 히트 시 카메라 임팩트·이펙트 연출.
  • 상태4(스테이지 실패): 실패 SFX와 함께 결과 화면 표시(제안).
  • 상태5(승리/클리어): 처치 이펙트와 클리어 안내 표시(제안).

14. 로딩·빈 상태·에러·100개 이상 데이터·3배 긴 텍스트 대응

  • 해당 항목에 대한 구체적 구현 근거(로딩 화면, 빈 상태 처리, 대용량 데이터 렌더링, 텍스트 오버플로우 대응) 파일은 확인되지 않음.
  • 현재 근거 부족으로 미구현 또는 미검증 상태로 판단(사실: 근거 부재).

15. 접근성

  • 접근성 관련(색맹 모드, 키 리매핑, 자막 등) 전용 구현 근거 파일이나 테스트가 확인되지 않음(사실: 근거 부재).
  • 게임패드/키보드 대체 입력 지원 여부는 미검증(제안).

16. 시각·청각·햅틱 피드백

  • 시각: 히트 플래시(heavy-hit-flash.png), 콤보 브러시 스미어(combo-brush-smear.png), 전기 볼트(electric-bolt.png) 등 이펙트 에셋 확인(사실).
  • 청각: 공격/닷지/피격/적 처치/스테이지 실패 SFX(Kenney 오디오 팩) 확인(사실).
  • 햅틱: 관련 구현 근거 파일 확인되지 않음(제안, 미구현 추정).

17. 구현 상태 매트릭스

  • 전투 피드백(ActionFeedback, ComboHitReaction, CombatFeedbackIntegration): 테스트 파일 존재 — 구현/검증 진행 중으로 추정(사실: 파일 존재).
  • 카메라 임팩트(CameraImpact, CameraImpactProfile): 테스트 파일 존재 — 구현 진행 중으로 추정(사실).
  • 경계벽 충돌(BoundaryWallIntegration), 캐릭터 매니저, 밸런스 설정: 테스트 파일 존재(사실).
  • 접근성, 로딩/빈 상태 처리: 근거 파일 미확인 — 미구현 또는 범위 밖으로 추정(사실: 근거 부재).
